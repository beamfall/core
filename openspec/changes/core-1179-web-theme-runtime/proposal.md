# Generated theme tokens and run-time themes in the web app

Ticket: CORE-1179 (`queue:core:main`).

## Why

The web app inlined a hand-copied `tokens.css` and carried raw `oklch()` and Tailwind palette
colours in its CSS and TSX, so it drifted from the design-system token release and could not be
re-skinned. ADR-0231 adds theme presets and theme documents resolved by a shared resolver (D5
layer order, D7 run-time seam, D10 preferences in `profile_client_prefs`); the web app needs to
apply them.

## What Changes

- `src/styles/tokens.css` and `src/lib/theme/theme.generated.ts` are generated by
  `scripts/generate-theme-tokens.mjs` from the latest published beamfall-design-system release
  and its preset catalog: the release CSS plus each shipped preset's resolved role values. The
  `design-token-drift` gate step and a Vitest check fail when either file drifts.
- `src/lib/theme/resolver.ts` is an original TypeScript resolver for theme documents; a Vitest
  suite runs it against the design system's golden vectors read from the sibling checkout.
- `src/styles/theme.css` maps the resolved roles onto the role names the styles use, and app CSS
  and TSX colour only through roles. `scripts/check-colour-literals.mjs` (part of `npm run check`)
  fails on any raw colour outside the generated file.
- `RegisterProvider` applies the chosen preset, or a theme document, as `--theme-*` custom
  properties on `<html>` without a reload, with a light, dark or system scheme per device stored
  in `localStorage` (`beamfall.web.appearance.v1`). The preset roams with the Profile as
  `theme.preset` in `profile_client_prefs`; Profile Settings gains an Appearance section.

## Non-goals

- No server endpoint or wire change. Roaming theme documents and the `theme.accent` layer are
  CORE-1184; this change reserves the key only.
- The resolver specification, its golden vectors and the preset documents stay in the design
  system (ADR-0231 ruling 3); core commits only derived values.
